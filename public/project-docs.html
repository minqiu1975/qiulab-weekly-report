1项目概述

QiuLab周报分析系统是为仇旻教授实验室（西湖大学）定制的周报管理与AI分析平台。系统支持32位实验室成员（研究员、博士后、博士生、本科生、访问学生）的周报上传、AI深度分析、趋势追踪、团队评估和跨设备数据同步。

核心能力

周报上传与分析

上传docx格式周报，Kimi k2.6自动为32人逐一分析并生成个性化研究建议

趋势可视化

每人独立趋势图，叠加静态基线与动态上传数据，支持16个时间点到最新周报

AI深度分析

每位成员可单独调用Kimi k2.6生成深度分析（进展/热点/建议/风险）

团队评估

6维度AI研判报告（工作负荷/质量/问题诊断/路径分析/行动建议/成果预测）

云端同步

Supabase云端同步，支持Edge/Firefox跨设备数据共享

成员管理

7类角色（研究员/副研/助研/博后/博士/本科/访问），支持编辑和新增

2功能清单

Dashboard 首页

  • 团队概览统计（总人数/评估人数/高风险/本周异常）
  • 个人评估分数条形图
  • 团队评分分布饼图（优秀/良好/需改进，含成员名字Tooltip）
  • 最近上传文件列表（动态读取，非硬编码）
  • 生成全组数据PDF报告（自动取最新一期数据）
  • "同步数据"按钮（手动触发云端拉取）

周报上传

  • 双文件上传（研究员+博后版 / 博士生版）
  • docx纯文本解析（mammoth库）
  • 重复检测（自动识别已上传日期，支持覆盖确认）
  • 显示完整文件名（非截断）
  • AI批量分析（32人并行，每批5人，调用Kimi k2.6）
  • 费用估算（~470 tokens/人，~0.005元/人）
  • 新成员自动检测（周报中发现不在成员列表的人名）
  • 上传历史记录（按周报日期分组显示）

趋势分析

  • 32人独立趋势图
  • 静态基线（10点）+ 动态数据（占位填充）合并显示
  • 16个X轴标签完整显示到最新上传日期
  • 多指标（进展/问题数/性格标签）

深度分析

  • 调用Kimi k2.6真实API（非模拟）
  • 分析结果持久化保存（localStorage + 云端同步）
  • 重新分析不销毁旧结果（确认后才覆盖）
  • 32人预生成分析数据（seed-deep-analyses.json）

分析页面

  • AI综合研判报告（6维度：进展/问题/路径/行动/文献/预测）
  • 最近一周摘要（静态+动态合并）
  • 历史摘要对比（最近4期）
  • 成员个人评分卡片（与团队分布同栏显示）
  • 深度分析按钮（Kimi k2.6实时调用）

设置页面

  • 团队成员管理（编辑/新增/角色修改）
  • 6类角色标签（研究员/副研/助研/博后/博士/本科/访问）
  • 入学年份选择（2020-2035）
  • Kimi API配置（端点选择+Key覆盖）
  • 云端同步配置（Supabase/百度网盘）
  • 数据迁移（JSON导出/导入）
  • 密码修改

4数据说明

数据存储方式

所有数据存储在浏览器 localStorage 中，通过云端同步实现跨设备共享。

localStorage Key 清单

Key数据内容类型
qlab_persons_v5团队成员信息JSON数组
qlab_dynamic_trends动态趋势数据（周→人→趋势）JSON对象
qlab_dynamic_history动态历史摘要（周→人→摘要）JSON对象
qlab_dynamic_labels趋势图X轴日期标签JSON数组
qlab_uploaded_dates已上传周报日期JSON数组
qlab_uploads上传历史记录JSON数组
qlab_deep_analyses深度分析结果JSON对象
qlab_last_modified最后修改时间戳ISO字符串
qlab_moonshot_api_keyKimi API Key（可选覆盖）字符串
qlab_moonshot_api_urlAPI端点（cn/ai）字符串
qlab_sync_config云端同步配置JSON对象

云端同步表

Supabase项目 qlab-sync，表 qlab_data，字段：

  • data - JSONB，包含 persons, dynamic, version, lastModified
  • updated_at - 更新时间
  • created_at - 创建时间

6维护指南

常见问题排查

分析页面不显示最新周报数据

检查 qlab_dynamic_trends 和 qlab_dynamic_labels 是否有最新日期的数据。确保上传后 localStorage 已更新。

趋势图只显示到4月3日/3月27日

检查 PERSON_BASELINE_TRENDS 中是否有足够数据点（需16个）。或检查 getMergedPersonTrend 是否正确合并动态数据。

深度分析结果丢失

检查 qlab_deep_analyses 是否有数据。确保分析完成后调用了 saveDeepAnalysis()。

云端同步失败

检查 Supabase 配置是否正确。检查浏览器控制台网络请求是否返回401/403。确认使用的是正确的API端点（cn/ai）。

新成员检测误报

检查 detectNamesFromReport 函数的排除词库是否完整。可根据实际周报格式调整正则表达式。
